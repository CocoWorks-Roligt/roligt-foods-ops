# B2 handoff — rules engine + server enforcement

## Module map (all pure, zero api/ imports; barrel `src/lib/rules.ts`)
- `rules/stateMachines.ts` — `canTransition`, `guardsRequired`, `evaluateGuards` (facts), plain-language explanations from contracts `LEGAL_TRANSITIONS`/`GUARD_EXPLANATIONS`.
- `rules/massBalance.ts` — `computeMassBalance`: count→kg via item `avgUnitWeight` (config `avgNutWeightG` g fallback), Litre→kg via `densityKgPerL`, kg/g passthrough; unknown conversion throws `MassBalanceError`; never sums mixed units raw.
- `rules/consumption.ts` — `canConsumeLot` (v2: Released-only all purposes; legacy: posting's DRAWABLE), `fefoOrder` strict/relaxed.
- `rules/spoilage.ts` — `closeRunGuards`: ≥1 record for that batch (qty 0 passes) + `withinTolerance`.
- `rules/cartons.ts` — `suggestCartons`, `planDeduction` (cartons only BOXED), `reconcileCartons`.
- `rules/flags.ts` — `readFlags`, `ALL_FLAGS_OFF`, `flagEnabled`.

## Enforcement wiring
`api/_lib/rulesGate.ts` (pure verdicts: `gateRules`, `rulesWantsEvidence`, `rulesAuditRow`) wired in `api/_lib/d1Commit.ts`: extra preflight SELECTs (flags/spoilage_records/items) only when the payload warrants; gate runs after `detectRowConflicts`; rejection writes an `audits` row (`action 'rules.rejected'`, details `{entity, guard}`) in its own atomic batch, then throws; `api/commit.ts` returns 422 `ApiError {error, code}`.

## Flag matrix
- `qc_gate_v2` — bulk draws (`Melange/Packing Consume`, `item_type 'Semi Finished'`, `qty_out>0`) with status ≠ Released → `lot_not_released`. PM/raw draws unaffected.
- `batch_v2` — close (Closed/Released) needs a spoilage record + recomputed balance in tolerance → else `spoilage_required`/`mass_balance_ok`. Unchanged-status edits and already-closed retries skipped.
- Both OFF — byte-for-byte legacy (commit-path tests prove it).
